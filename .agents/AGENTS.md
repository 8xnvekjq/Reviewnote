# 프로젝트 버전 관리 행동 규칙 (Workspace Rules)

## 📌 버전 인상 및 배포 주기 속도 조절 룰
1. 항상 코드 수정, 삭제 전에 미리 지시내용을 물어보고 AI가 할 행동을 수행해도 될지 물어보고 행동
2. 자잘한 디자인 피드백, 레이아웃 미세 조정, 배지 문구 수정 등 마이크로 단위의 수정 사항은 \`package.json\` 버전을 매번 올리지 않고 그대로 보존하거나 커밋만 쌓아둡니다.
3. 의미 있는 수준 높은 개선 사항들이 **3~4개 이상 모여** 선생님께서 실서버 테스트를 마치시고 만족하셨을 때, 배포 시점에 비로소 하나의 완성된 기능 단위(예: \`v1.9.0\` 또는 \`v1.8.4\` 등)로 버전을 한꺼번에 통합 판 올림 합니다.
4. 이 규칙은 오답노트 프로젝트에 참여하는 모든 AI 코딩 에이전트에게 예외 없이 엄격하게 강제 적용됩니다.
5. 시키는 것만 하고 애매할 경우에는 물어보고 행동하기
6. **스크립트 재사용 및 무분별한 신규 생성 금지 룰**: 반복적/유사한 작업을 수행할 때 매번 일회성 `.js` 파일(예: `test_v1.js`, `process_v2.js` 등)을 새로 생성하지 않으며, `scripts/` 디렉토리에 등록된 대표 공용 스크립트를 재사용하고 명세(`scripts/README.md`)를 상시 유지 관리합니다.
7. **AI 코딩 에이전트 간 분업 및 협업 지침 (Antigravity & Claude Code)**:
   - **Google Antigravity (팀장/오케스트레이터)**: UI/UX 반응형 프론트엔드 디자인, 애니메이션 이펙트, Supabase DB 연동, 럭키상점 비주얼 시스템, 사용자 소통 및 최종 빌드/배포 전담.
   - **Claude Code (정밀 파트너)**: 대규모 코드베이스 타입 스캔 및 검증, 복잡한 수학/알고리즘 연산 최적화, 엣지케이스 에러 트레이싱, 단위 테스트(Unit Test) 대량 자동 생성 전담.
   - 모든 AI 에이전트는 코드 수정 전 선생님께 의도를 전달하고, 마이크로 수정 시 package.json 버전을 올리지 않고 그대로 유지합니다.
