# 시험 필기 동기화와 관리자 조회

## 변경 내용

- 답안·응시·점수는 기존에도 서버 저장이었다. 기기 전용이던 손글씨를 `exam_attempt_ink`에 응시/문항별로 저장한다.
- 획 변경마다 IndexedDB에 복구용 초안을 남기고, 800ms 뒤 서버에 전송한다. 실패한 전송은 온라인 복귀 또는 10초 간격으로 재시도한다.
- 나가기·제출은 필기 저장 완료를 기다린다. 실패하면 화면을 유지하고 안내한다. 브라우저 강제 종료 시 서버 전송은 보장할 수 없으므로 원래 기기의 초안으로 복구한다.
- 서버 revision으로 다른 기기의 변경을 감지한다. 충돌 시 자동 덮어쓰기를 멈추고, 사용자 확인 후 서버 필기를 불러올 수 있다. 여러 기기의 동시 편집을 병합하는 기능은 아니다.
- 기존 IndexedDB 필기는 원래 기기에서 해당 풀이/결과를 열 때, 서버에 없는 문항만 옮긴다. 제출된 시험도 최초 이관은 가능하지만 서버에 저장된 제출 후 필기를 다시 수정할 수는 없다. 이미 지워진 기기 저장 데이터는 복원할 수 없다.
- 학생은 자신의 필기만 조회·저장한다. 관리자는 학생 상세 → 시험 풀이 기록에서 시험명, 회차, 응시 일시, 진행 상태, 점수를 확인하고 문항별 답안·필기를 읽기 전용으로 본다. 관리자 직접 풀기는 관리자의 기존 시험 풀이 화면으로 이동한다.
- 한능검은 원본 페이지를 공유하는 문항들의 필기를 첫 문항 ID에 저장하는 기존 방식과 동일하다.

## 운영 적용

`supabase/migrations/20261003010000_exam_ink_sync_admin.sql`을 기존 한능검 마이그레이션 다음에 적용한 뒤 프런트엔드를 배포한다. CLI로 만든 새 마이그레이션의 시간 접두사는 기존 파일들이 미래 시각을 사용하고 있어 의존성 뒤로 조정했다.

이 작업에서는 운영 DB 적용·배포·push를 하지 않았다. 기존 마이그레이션과 패키지 버전/lockfile은 수정하지 않았다.

추가 테이블은 RLS를 켜고 직접 쓰기를 금지한다. RPC에서 본인/관리자 권한, 응시 문항 소속, 필기 구조·크기, 저장 revision을 검증한다. 관리자 목록은 학생별 30개 단위로 조회한다. 필기는 문항당 JSON 2MiB, 최대 2,000획을 허용한다.

## 필기 과정 재생 검토 — 구현하지 않음

가능하다. 영상 파일을 녹화할 필요 없이 필기 변경을 순서대로 기록하고 캔버스에서 재현하면 된다.

현재 `InkStroke[]`는 남아 있는 획의 순서를 유지하고 `InkPoint.t`는 **각 획을 시작한 뒤의 상대 시간**이다. 따라서 남은 획을 하나씩 표시하는 근사 재생은 가능하다. 다만 지우개로 삭제된 획, 실행 취소/다시 실행, 전체 지우기, 획 사이의 대기 시간은 최종 데이터만으로 복원할 수 없다. 도형 보정도 원래 손 움직임을 바꾸므로 기존 필기의 정확한 작성 과정을 소급 재현할 수 없다.

새 필기부터 다음 방식으로 기록하는 것이 적절하다.

1. 획 추가, 지운 획 ID, 실행 취소/다시 실행, 전체 지우기를 순번이 있는 이벤트로 저장한다.
2. 기기별 세션 ID, 이벤트 ID, 상대 시간으로 중복 전송과 기기 시계 차이를 다룬다. 재접속 시 순서를 유지한다.
3. 펜을 뗄 때 또는 짧은 묶음 단위로 전송한다. 매 포인터 이벤트마다 DB에 요청하지 않는다.
4. 일정 간격의 스냅샷을 함께 두어 중간 시점으로 빠르게 이동한다.
5. 관리자 화면에 이전/다음 단계, 재생/정지, 배속, 긴 멈춤 건너뛰기를 제공한다. 첫 구현은 획 단위 단계 재생만으로 충분하다.

이벤트 저장은 현재 최종 필기 저장보다 저장량이 늘고, 오프라인 재전송·충돌·보존 기간 정책이 필요하다. 실제 비용과 용량은 학생들의 표본 필기로 측정해야 한다. 교사가 보는 것은 작성 순서의 기록이며 학생의 생각 자체를 확정하는 자료는 아니다. 실시간 중계 없이 저장 후 재생부터 구현할 수 있다.

## 검증

- 시험 기능 Node 테스트 및 PGlite에서 실제 SQL/RLS/RPC 적용 테스트.
- 별도 기기 캐시, 동시 저장 충돌, 삭제 유지, 오프라인 초안 복구, 기존 필기 이관, 저장 중 추가 필기, 권한 거부 테스트.
- 브라우저 하네스에서 기존 풀이/제출/이어 풀기 흐름, IndexedDB가 없는 다른 브라우저의 필기 복원, 관리자 제출/진행 중 풀이 읽기 전용 조회와 모바일 레이아웃 검증.
- TypeScript, oxlint, 프로덕션 빌드. 실제 운영 로그인/DB 연결 검증은 운영 적용 후 필요하다.
